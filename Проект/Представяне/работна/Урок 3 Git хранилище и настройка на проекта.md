# 1. Основни понятия и дефиниции

| Термин | Кратко определение |
|---|---|
| **Git** | Разпределена система за контрол на версиите. Пази историята на промените по файловете. |
| **Хранилище (repository)** | Папка на проекта, в която Git следи файловете и записва историята на промените. |
| **Локално хранилище** | Хранилище, създадено и съхранявано на компютъра на разработчика. |
| **Commit** | Запис на логически завършен набор от промени в историята на проекта. |
| **Staging area** | Междинна зона: файловете, избрани за включване в следващия commit. |
| **`.gitignore`** | Файл с правила за файлове и папки, които Git не трябва да проследява. |
| **Виртуална среда** | Самостоятелна среда с Python и библиотеки за конкретен проект. |
| **`git status`** | Команда, която показва състоянието на файловете в Git хранилището. |

## Защо използваме Git?

Git помага да:

- видим какво е променено и кога;
- върнем по-стара версия при грешка;
- работим по един проект с други програмисти;
- записваме промените на малки, ясни етапи;
- избегнем изпращането на файлове през чат или електронна поща.

# 2. Организация на началния Python проект

Добрата структура прави проекта по-лесен за разбиране, тестване и поддръжка.

```text
student_planner/
├── src/
│   └── main.py
├── tests/
│   └── test_main.py
├── docs/
├── data/
├── README.md
└── .gitignore
```

## Предназначение на папките и файловете

| Елемент | Предназначение |
|---|---|
| `src/` | Съдържа изходния код на приложението. |
| `src/main.py` | Начална входна точка на програмата. |
| `tests/` | Съдържа тестове за проверка на кода. |
| `docs/` | Съдържа допълнителна документация. |
| `data/` | Съдържа примерни или входни данни, ако проектът ги използва. |
| `README.md` | Описва каква е целта на проекта и как се стартира. |
| `.gitignore` | Определя кои локални или генерирани файлове не се добавят в Git. |

## Правила за именуване

- Използвайте кратки и ясни имена.
- За Python файлове използвайте малки букви и долна черта: `task_manager.py`.
- Не използвайте интервали и неясни имена като `new.py`, `test2.py` или `final_final.py`.
- Поддържайте еднаква структура за всички членове на екипа.

# 3. Настройване на Python проект в PyCharm

## Стъпка 1: Създаване на проект

1. Отворете PyCharm.
2. Изберете **New Project**.
3. Въведете име, например `student_planner`.
4. Изберете Python интерпретатор с нова виртуална среда `.venv`.
5. Изберете **Create**.

## Защо е нужна виртуална среда?

Различните проекти могат да използват различни версии на библиотеки. Виртуалната среда изолира зависимостите на един проект от тези на друг проект.

> **Важно:** Папката `.venv` обикновено не се качва в Git. Тя се създава локално на всеки компютър.

## Стъпка 2: Създаване на начални папки и файлове

В прозореца **Project** на PyCharm:

1. Създайте папки `src`, `tests`, `docs` и `data`.
2. В `src` създайте Python файл `main.py`.
3. В основната папка създайте `README.md`.
4. В основната папка създайте файл `.gitignore`.

# 4. Файлът `.gitignore`

`.gitignore` казва на Git кои файлове и папки да не включва в хранилището. Обикновено това са автоматично генерирани файлове, лични настройки или чувствителни данни.

## Примерен `.gitignore` за Python проект в PyCharm

```gitignore
# Виртуални среди
.venv/
venv/

# Python кеш и компилирани файлове
__pycache__/
*.pyc

# Настройки на PyCharm
.idea/

# Локални променливи и чувствителни данни
.env

# Отчети от тестове
.coverage
htmlcov/
```

## Как се четат правилата?

- `.venv/` — игнорира цялата папка `.venv`.
- `__pycache__/` — игнорира автоматично създадените Python кеш папки.
- `*.pyc` — игнорира всички файлове с разширение `.pyc`.
- `.idea/` — игнорира личните настройки на PyCharm.
- `.env` — игнорира файл, в който често се пазят ключове, пароли или локални настройки.

> **Внимание:** Ако файл вече е добавен и commit-нат, записването му в `.gitignore` не го премахва автоматично от историята. Затова е добра практика `.gitignore` да бъде създаден преди първия commit.

# 5. Създаване на локално Git хранилище в PyCharm

## Вариант A: Чрез графичния интерфейс на PyCharm

1. Отворете проекта в PyCharm.
2. Изберете **VCS → Enable Version Control Integration**.
3. Изберете **Git**.
4. PyCharm създава Git хранилище в основната папка на проекта.
5. Отворете прозореца **Commit**, за да видите новите и променените файлове.

След активиране на Git в папката на проекта се създава скрита папка `.git`. Тя съдържа историята и настройките на локалното хранилище.

> **Не изтривайте папката `.git` и не я променяйте ръчно.** Без нея проектът вече няма да бъде разпознат като Git хранилище.

## Вариант B: Чрез терминал

Отворете терминал в основната папка на проекта и изпълнете:

```bash
git init
```

Тази команда инициализира празно локално Git хранилище.

# 6. Проверка на състоянието на проекта

Използвайте следната команда в терминал:

```bash
git status
```

Git може да покаже различни състояния:

| Състояние | Значение |
|---|---|
| `Untracked files` | Нови файлове, които Git още не проследява. |
| `Changes not staged for commit` | Проследявани файлове, които са променени, но не са избрани за следващия commit. |
| `Changes to be committed` | Файлове, подготвени за следващия commit. |
| `nothing to commit, working tree clean` | Няма нови промени; работната папка е чиста. |

## Основна схема на работа

```text
Променям файл
      ↓
git status
      ↓
git add .
      ↓
git commit -m 'Смислено съобщение'
      ↓
git status
```

# 7. Първи commit

Първият commit обикновено записва началната структура и първите файлове на проекта.

## Чрез терминал

```bash
# Показва какво е ново или променено
git status

# Добавя всички подходящи файлове от текущата папка
git add .

# Създава запис в историята на проекта
git commit -m 'Initial project structure'

# Показва кратка история на commit-ите
git log --oneline
```

## Чрез PyCharm

1. Отворете прозореца **Commit**.
2. Проверете кои файлове са избрани.
3. Уверете се, че `.venv`, `.idea` и `__pycache__` не се добавят.
4. Напишете ясно съобщение.
5. Натиснете **Commit**.

## Как изглежда добро commit съобщение?

Добро съобщение е кратко, конкретно и описва извършената промяна.

| Подходящо | Неподходящо |
|---|---|
| `Initial project structure` | `Changes` |
| `Add gitignore for Python project` | `Update` |
| `Add initial task function` | `123` |
| `Add tests for add_task` | `Оправих нещо` |

# 8. Демо код: начален Python файл

Създайте файла `src/main.py` и добавете следния код:

```python
def greet_user(name):
    # Връща текстово приветствие към потребителя.
    return f'Здравей, {name}! Проектът е настроен успешно.'


def main():
    # Това е началната функция на приложението.
    message = greet_user('Разработчик')
    print(message)


if __name__ == '__main__':
    # Изпълнява main() само когато файлът е стартиран директно.
    main()
```

### Обяснение на ключовите редове

- `def greet_user(name):` създава функция с параметър `name`.
- `return` връща резултат от функцията.
- `def main():` определя началната логика на приложението.
- `if __name__ == '__main__':` проверява дали файлът е стартиран директно.
- `main()` извиква началната функция.

Очакван резултат:

```text
Здравей, Разработчик! Проектът е настроен успешно.
```

# 9. Демо код: малка функционалност и тест

В началния проект може да добавите проста функция за работа със задачи.

## Файл `src/main.py`

```python
def add_task(tasks, title):
    # Добавя нова задача в списъка.
    tasks.append(title)
    return f'Добавена е задача: {title}'


def main():
    tasks = []
    result = add_task(tasks, 'Подготовка за лабораторен практикум')
    print(result)
    print(f'Общ брой задачи: {len(tasks)}')


if __name__ == '__main__':
    main()
```

## Файл `tests/test_main.py`

```python
from src.main import add_task


def test_add_task():
    # Подготвя празен списък със задачи.
    tasks = []

    # Извиква функцията, която тестваме.
    result = add_task(tasks, 'Тестова задача')

    # Проверява дали задачата е добавена.
    assert tasks == ['Тестова задача']

    # Проверява дали е върнато очакваното съобщение.
    assert result == 'Добавена е задача: Тестова задача'
```

# 10. Работа в екип: основни правила

При работа по общ проект следвайте тези правила:

1. **Правете малки commit-и.** Един commit трябва да съдържа една логически свързана промяна.
2. **Използвайте ясни съобщения.** Друг член на екипа трябва да разбере какво е променено.
3. **Не качвайте пароли и ключове.** Файлове като `.env` трябва да бъдат игнорирани.
4. **Не качвайте локални настройки и виртуални среди.** Те се създават на всеки компютър.
5. **Поддържайте еднаква структура.** Екипът трябва да знае къде се намират кодът, тестовете и документацията.
6. **Проверявайте `git status`.** Направете го преди и след commit.

# 11. Внимание: чести грешки и добри практики

## Чести грешки

- Добавяне на `.venv/` в Git хранилището.
- Добавяне на папката `.idea/` с лични настройки на IDE.
- Използване на неясни commit съобщения като `Update` или `Changes`.
- Извършване на много различни промени в един commit.
- Създаване на `.gitignore` след като ненужните файлове вече са commit-нати.
- Изтриване или ръчна промяна на папката `.git`.
- Непроверяване на `git status` преди commit.

## Добри практики

- Създавайте `.gitignore` още в началото на проекта.
- Правете commit след всяка завършена малка стъпка.
- Проверявайте списъка с файлове преди потвърждаване на commit.
- Поддържайте `README.md` актуален.
- Използвайте еднакви правила за именуване в целия екип.
