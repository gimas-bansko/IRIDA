## 1. Въведение и цели на темата

Всеки път, когато отворим уебсайт, браузърът обменя съобщения със сървъри: заявява HTML страница, стилове, изображения, JavaScript файлове или данни от API. Умението да наблюдаваме този обмен е основно за уеб разработчици, системни програмисти и специалисти по поддръжка, защото помага бързо да откриваме защо даден ресурс не се зарежда или защо приложение връща грешка.

В този урок ще използваме **Browser DevTools** и раздела **Network**, за да видим реални HTTP/HTTPS заявки и отговори.

### След този урок ще можете да...

- отваряте DevTools и наблюдавате заявките в раздел **Network**;
- разпознавате **HTTP метод**, **URL**, **query параметри** и **request headers**;
- разчитате **status code**, **response headers** и **body** на HTTP отговор;
- обяснявате значението на чести кодове: `200`, `301/302`, `404` и `500`;
- документирате кратък технически анализ на реална заявка, без да разкривате чувствителни данни.

## 2. Основни понятия и дефиниции

### 2.1. Какво е мрежов протокол?

**Мрежов протокол** е набор от правила, по които устройства и програми обменят данни в мрежа. Той определя как изглеждат съобщенията, как се изпращат и как се тълкуват.

Примери:

- **IP** — адресира устройства и маршрутизира пакети в мрежата;
- **TCP** — осигурява надеждна доставка на данни;
- **DNS** — преобразува име на домейн, например `example.com`, в IP адрес;
- **HTTP** — пренася уеб заявки и отговори между клиент и сървър;
- **HTTPS** — HTTP, защитен чрез криптиране с TLS.

### 2.2. Клиент, сървър и HTTP

- **Клиент** — програма, която изпраща заявка. В нашия урок това най-често е браузърът.
- **Сървър** — програма или компютърна система, която приема заявката, обработва я и връща отговор.
- **HTTP** (_HyperText Transfer Protocol_) — приложен протокол за обмен на уеб данни.
- **HTTPS** — защитен вариант на HTTP. Данните се криптират по време на преноса между браузъра и сървъра.

### 2.3. Схема на HTTP комуникацията

```text
Браузър (клиент)                         Уеб сървър
       |                                      |
       | ---- HTTP заявка: GET /products ---->|
       |                                      |
       |<--- HTTP отговор: 200 OK + JSON -----|
       |                                      |
```

Важно: при една отворена страница обикновено има **много заявки** — за HTML, CSS, JavaScript, изображения, шрифтове, данни от API и други ресурси.

## 3. HTTP заявка: основни части

HTTP заявката е съобщение, с което клиентът иска ресурс или действие от сървъра.

### 3.1. Метод (HTTP Method)

Методът показва какво действие иска да извърши клиентът.

| Метод | Значение | Типичен пример |
|---|---|---|
| `GET` | Заявява ресурс или данни | Зареждане на страница или списък с продукти |
| `POST` | Изпраща данни за обработка/създаване | Изпращане на форма за регистрация |
| `PUT` | Заменя или актуализира ресурс | Обновяване на цял профил |
| `PATCH` | Частично актуализира ресурс | Промяна само на име или адрес |
| `DELETE` | Заявява изтриване на ресурс | Изтриване на запис |

**Правило за запомняне:** `GET` основно чете данни; `POST` основно изпраща данни за обработка.

### 3.2. URL (адрес на заявката)

Примерен адрес:

```text
https://httpbin.org/get?class=12&topic=http
```

Разчитане:

| Част | Пример | Значение |
|---|---|---|
| Протокол | `https://` | Използваният протокол за комуникация |
| Домейн | `httpbin.org` | Име на сървъра/услугата |
| Път | `/get` | Конкретен ресурс или endpoint |
| Query string | `?class=12&topic=http` | Допълнителни параметри към заявката |

### 3.3. Query параметри

**Query параметрите** се намират след символа `?` в URL. Отделните параметри обикновено се разделят със символа `&`.

```text
https://example.org/search?q=http&page=2
```

В примера:

- `q=http` — параметър за търсене;
- `page=2` — номер на страница.

### 3.4. Request headers

**Request headers** са допълнителни метаданни, които браузърът изпраща към сървъра.

| Header | Какво показва |
|---|---|
| `Accept` | Какви формати клиентът може да приеме |
| `User-Agent` | Информация за браузъра и устройството |
| `Accept-Language` | Предпочитани езици на клиента |
| `Content-Type` | Формат на изпращаното тяло, например JSON |
| `Authorization` | Данни за удостоверяване при защитени ресурси |

> **Внимание:** Не копирайте, не публикувайте и не споделяйте стойности на `Authorization`, cookies, токени, сесийни идентификатори или лични данни.

## 4. HTTP отговор: основни части

HTTP отговорът е съобщението, което сървърът връща след обработване на заявката.

### 4.1. Status code

**Status code** е числов код, който показва резултата от обработването на заявката.

| Група | Значение |
|---|---|
| `1xx` | Информационни отговори |
| `2xx` | Успешно обработени заявки |
| `3xx` | Пренасочвания |
| `4xx` | Грешка от страна на клиента или заявката |
| `5xx` | Грешка от страна на сървъра |

### 4.2. Най-чести кодове за състояние

| Код | Наименование | Значение в практиката |
|---|---|---|
| `200 OK` | Успех | Ресурсът или данните са върнати успешно |
| `201 Created` | Създадено | Успешно е създаден нов ресурс |
| `301 Moved Permanently` | Трайно пренасочване | Адресът на ресурса е променен трайно |
| `302 Found` | Временно пренасочване | Клиентът трябва временно да използва друг адрес |
| `400 Bad Request` | Невалидна заявка | Изпратените данни или форматът на заявката са неправилни |
| `401 Unauthorized` | Нужна идентификация | Необходимо е удостоверяване |
| `403 Forbidden` | Достъпът е отказан | Сървърът разбира заявката, но не разрешава достъп |
| `404 Not Found` | Не е намерено | Заявеният ресурс липсва на този адрес |
| `500 Internal Server Error` | Сървърна грешка | Възникнал е проблем при обработката на сървъра |

**Важно разграничение:** `404 Not Found` не означава непременно, че няма интернет. Често означава, че сървърът е достъпен, но ресурсът не съществува на заявения URL.

### 4.3. Response headers и body

- **Response headers** — метаданни, върнати от сървъра.
- **Response body** — самото съдържание на отговора: HTML, JSON, изображение, текст или друго.

Примерни response headers:

| Header | Значение |
|---|---|
| `Content-Type: text/html` | Отговорът съдържа HTML документ |
| `Content-Type: application/json` | Отговорът съдържа JSON данни |
| `Cache-Control` | Правила за кеширане |
| `Location` | Нов адрес при пренасочване (`301`, `302`) |
| `Content-Length` | Размер на отговора в байтове |

## 5. Практикум: Анализ в DevTools → Network

### 5.1. Отваряне на DevTools

В Chrome, Edge и други Chromium-базирани браузъри:

- натиснете `F12`; или
- натиснете `Ctrl + Shift + I`; или
- щракнете с десен бутон върху страница и изберете **Inspect / Проверка**.

След това изберете раздел **Network**.

### 5.2. Основни стъпки за анализ

1. Отворете **DevTools**.
2. Изберете раздел **Network**.
3. Презаредете страницата с `Ctrl + R`.
4. Наблюдавайте списъка със заявки.
5. Изберете една заявка.
6. Отворете детайлите: **Headers**, **Payload**, **Preview** и **Response**.
7. Документирайте най-важните данни.

### 5.3. Какво показват основните колони в Network?

| Колона | Значение |
|---|---|
| `Name` | Име или част от адреса на заявения ресурс |
| `Status` | Кодът на HTTP отговора |
| `Type` | Тип на ресурса: документ, скрипт, изображение, Fetch/XHR и др. |
| `Initiator` | Какво е предизвикало заявката |
| `Size` | Размер на получения ресурс |
| `Time` | Време за изпълнение на заявката |

### 5.4. Полезни филтри

| Филтър | Кога го използваме |
|---|---|
| `Doc` | За основния HTML документ |
| `Fetch/XHR` | За заявки от JavaScript към API |
| `JS` | За JavaScript файлове |
| `CSS` | За CSS файлове |
| `Img` | За изображения |
