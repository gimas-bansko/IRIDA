## 1. Защо изучаваме тази тема?

Когато отворите уеб страница, браузърът и сървърът обменят съобщения по определени правила. Разбирането на този обмен помага да откривате причините за неработещ адрес, липсваща страница или проблем със защитата на връзката. Това е първата стъпка към създаването на собствени уеб приложения.

### След този урок ще можете да:

- Отделяте схемата, името или IP адреса на сървъра и пътя в примерен URL.
- Обяснявате основната разлика между HTTP и HTTPS.
- Разграничавате защитена връзка от достоверно съдържание.

## 2. Интернет и уеб не са едно и също

**Интернет** е глобална система от взаимосвързани компютърни мрежи. По нея се предават данни между устройства.

**Уеб (Web)** е услуга за достъп до страници и други свързани ресурси чрез Интернет или локална мрежа.

**Браузърът** е програма за достъп до уеб съдържание — например Firefox, Chrome или Edge. Той не е самият Интернет.

```text
Интернет — мрежова инфраструктура
├── Уеб — страници и уеб приложения
├── Електронна поща
└── Други мрежови услуги
```

**Ресурс** наричаме нещо, до което можем да получим достъп: HTML страница, изображение, файл или данни от приложение.

### Внимание: честа грешка

Липсата на достъп до един сайт не означава непременно липса на Интернет. Възможно е само този сървър да не работи или конкретният адрес да е грешен.

## 3. Клиент, сървър и мрежов протокол

### Основни понятия

| Понятие | Значение | Пример |
|---|---|---|
| Клиент | Програма, която изпраща заявка за ресурс или действие | Браузър |
| Сървър | Програма, която приема заявки и връща отговори | Локален Python HTTP сървър |
| Мрежов протокол | Правила за формата и обмена на съобщения | HTTP |

Думата **сървър** често обозначава и компютъра, на който работи сървърният софтуер. В този урок разграничаваме преди всичко ролите на програмите.

### Моделът клиент–сървър

```text
                  заявка за ресурс
Браузър (клиент) ─────────────────────→ Уеб сървър
Браузър (клиент) ←───────────────────── Уеб сървър
                 отговор с резултат
```

Клиентът и сървърът могат да работят на различни компютри или на една и съща машина. Ролите им се определят от това какво правят, а не от физическото им местоположение.

### Пътят на една заявка — опростено

1. Въвеждате URL в браузъра.
2. Ако адресът съдържа име на сървър, браузърът използва DNS информация, за да намери съответния IP адрес.
3. Установява се връзка със сървъра; при HTTPS се договаря и TLS защита.
4. Браузърът изпраща HTTP заявка.
5. Сървърът обработва заявката и връща HTTP отговор.
6. Браузърът обработва получения резултат и показва съдържанието.

**DNS** е система, която помага имената на сървъри да бъдат свързвани с IP адреси. Част от информацията може вече да е запазена, затова не всяко отваряне изисква ново DNS търсене.

> **Запомнете:** Една страница често изисква няколко заявки — за HTML, изображения, CSS и JavaScript. Браузърът може и да използва запазени копия на ресурси, наречени кеш.

## 4. URL — как да разчетем уеб адреса?

**URL (Uniform Resource Locator)** е адрес, който указва как и къде да се достъпи ресурс.

### Основна структура

```text
схема://сървър[:порт]/път
```

Квадратните скоби тук означават незадължителна част. Те не се изписват в самия адрес.

### Пример 1: адрес с име на сървър

```text
https://example.com/catalog/item.html
```

| Част | Стойност | Какво показва? |
|---|---|---|
| Схема | `https` | Използване на HTTPS |
| Име на сървъра | `example.com` | Към кой сървър е насочен адресът |
| Път | `/catalog/item.html` | Кой ресурс се заявява |

### Пример 2: локален адрес с IP и порт

```text
http://127.0.0.1:8000/index.html
```

| Част | Стойност | Какво показва? |
|---|---|---|
| Схема | `http` | Използване на HTTP |
| IP адрес | `127.0.0.1` | Собствената машина |
| Порт | `8000` | Номер на порта, на който слуша учебният сървър |
| Път | `/index.html` | Заявения ресурс |

**127.0.0.1** е адрес за връзка със собствената машина. На вашия компютър той не сочи към компютъра на преподавателя.

**Портът** помага връзката да достигне до определена мрежова услуга. Когато не е посочен изрично, обичайните портове са 80 за HTTP и 443 за HTTPS. За този урок не е необходимо да ги запаметявате.

### Правило за разчитане

1. Потърсете `://` — преди него е схемата.
2. След него намерете името или IP адреса на сървъра.
3. Ако след сървъра има двоеточие и число, числото е портът.
4. Следващата част, започваща с `/`, е пътят.

Това правило е достатъчно за простите адреси в урока. В реални приложения използвайте готови библиотеки за разчитане на URL.

### Внимание: чести грешки

- Пътят не е част от името на сървъра: в `example.com/help/` сървърът е `example.com`.
- Пътят не е задължително физически файл. Например `/tasks/` може да бъде обработен от Django приложение.
- Правилно изглеждащ URL не доказва, че сървърът работи или ресурсът съществува.

### По желание: параметри и фрагмент

```text
https://example.com/search?q=python#results
```

- Път: `/search`.
- Параметри на заявката: `q=python` след `?`.
- Фрагмент: `results` след `#` — използва се от браузъра и не се изпраща като част от HTTP заявката към сървъра.

Тези части са разширение и не са задължителни за основните задачи.

## 5. HTTP — заявка и отговор

**HTTP (Hypertext Transfer Protocol)** е приложен протокол за обмен на заявки и отговори.

### Какво съдържат съобщенията?

| HTTP заявка | HTTP отговор |
|---|---|
| Метод — какво действие се иска | Статус — какъв е резултатът |
| Път към ресурса | Заглавки с допълнителна информация |
| Заглавки с допълнителна информация | Възможно тяло: HTML, изображение, данни |
| Възможно тяло с изпратени данни | Някои отговори нямат тяло |

Днес е достатъчно да разпознавате **GET** като метод за извличане на ресурс. Различните HTTP методи ще бъдат разгледани в следващ урок.

### Опростен пример с HTTP/1.1

Заявка:

```http
GET /index.html HTTP/1.1
Host: 127.0.0.1:8000

```

Първият ред показва метода, пътя и версията на протокола. Заглавката `Host` посочва сървъра и порта.

Опростен отговор с пропуснати технически заглавки:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<h1>Здравей!</h1>
```

`200 OK` показва успешна обработка. `Content-Type` описва вида на съдържанието. След празния ред започва тялото на отговора.

Това е учебна илюстрация на текстовия вид на HTTP/1.1. Не е точен запис на всяка браузърна връзка: съществуват и други версии на HTTP.

### Няколко статуса за ориентация

| Статус | Значение |
|---|---|
| `200 OK` | Заявката е успешна |
| `404 Not Found` | Заявеният ресурс не е намерен |
| `500 Internal Server Error` | Възникнала е вътрешна грешка на сървъра |

> **Добра практика:** Четете адреса и статуса, преди да променяте кода. Грешен път и спрян сървър са различни проблеми. При отказана връзка може изобщо да няма HTTP отговор и статус.

## 6. HTTP и HTTPS — каква е разликата?

**HTTPS** е HTTP комуникация, защитена чрез **TLS (Transport Layer Security)**.

| Особеност | HTTP | HTTPS |
|---|---|---|
| Схема в URL | `http` | `https` |
| TLS защита на обмена | Не | Да |
| Поверителност и защита от промяна чрез TLS | Не | Да |
| Проверка на сървъра чрез TLS сертификат | Не | Да |

TLS осигурява:

- **Поверителност:** предаваните данни са криптирани.
- **Цялост:** защитата позволява да бъде открита неразрешена промяна на данните при пренос.
- **Удостоверяване на сървъра:** браузърът проверява сертификата за съответното име на сървъра.

### Защитена връзка ≠ достоверно съдържание

Сайт с HTTPS може да съдържа неверни твърдения или да бъде измамен. HTTPS защитава обмена с посочения сайт, но не оценява истинността на написаното и намеренията на неговия собственик.

**Добри практики:**

- Проверявайте внимателно името на сайта, а не само наличието на `https`.
- Не пренебрегвайте предупреждения за невалиден сертификат.
- Не изпращайте пароли или други чувствителни данни през незащитена публична HTTP връзка.

Иконите в адресната лента се различават между браузърите. Не свеждайте обяснението на HTTPS само до наличието на катинар.

## 7. Демонстрация: локален HTTP сървър с Python

### Какво наблюдаваме?

Браузърът и Python сървърът работят на един компютър. Ще проследим заявката за HTML файл и получения отговор.

**Необходими средства:** Python 3, браузър и отделна учебна папка. Интернет не е необходим.

### Стъпка 1: Подгответе HTML файл

В нова учебна папка създайте `index.html`:

```html
<!doctype html>
<html lang='bg'>
<head>
  <meta charset='utf-8'>
  <title>Пътят на заявката</title>
</head>
<body>
  <!-- Това съдържание ще бъде изпратено от сървъра. -->
  <h1>Здравей от локалния сървър!</h1>
  <p>Браузърът получи този HTML чрез HTTP.</p>
</body>
</html>
```

`charset='utf-8'` позволява правилно представяне на кирилицата. Елементите в `body` са видимото съдържание. HTML ще се изучава подробно по-късно.

### Стъпка 2: Стартирайте сървъра

Отворете терминал **в папката с файла** и изпълнете:

```shell
python -m http.server 8000 --bind 127.0.0.1
```

| Част от командата | Значение |
|---|---|
| `python` | Стартира Python |
| `-m http.server` | Изпълнява вградения модул за HTTP сървър |
| `8000` | Избира порт 8000 |
| `--bind 127.0.0.1` | Ограничава достъпа до собствената машина |

Ако във вашата среда командата е `python3` или `py`, използвайте нея вместо `python`. Оставете терминала отворен.

### Стъпка 3: Отворете страницата

В адресната лента въведете:

```text
http://127.0.0.1:8000/index.html
```

Не отваряйте файла само с двойно щракване: адрес от вида `file:///...` не демонстрира HTTP обмен със сървъра.

### Стъпка 4: Наблюдавайте заявката

1. Отворете инструментите за разработчици от менюто на браузъра или с `F12`, ако клавишът се поддържа.
2. Изберете **Network** и презаредете страницата.
3. Изберете заявката за `index.html`.
4. Намерете **Request URL**, **Request Method** и **Status Code**.
5. Сравнете заявката със записа в терминала на Python сървъра.

При първо успешно некеширано зареждане очаквайте метод `GET` и статус `200`. При повторно зареждане може да видите `304`, свързан с използване на кеш. За по-ясна демонстрация включете **Disable cache**, докато инструментите са отворени, и презаредете.

Браузърът може да поиска и `favicon.ico`. Това е отделен ресурс, а не основният HTML документ.

### Стъпка 5: Спрете сървъра

В терминала натиснете `Ctrl+C`. Вече показаната страница може да остане видима — това не означава, че сървърът продължава да работи.

### Внимание и добри практики

- Използвайте отделна папка без лични документи: файловият сървър може да обслужва файловете в нея.
- Този сървър е само за локална учебна демонстрация, не за публичен сайт.
- Ако порт 8000 е зает, преподавателят може да избере 8001; тогава променете порта и в URL.
- При липса на Python анализирайте предоставена снимка на Network и схемата на обмена. Основните цели не изискват инсталиране на софтуер.

## 8. Python пример: разчитане на URL

Този пример **не изпраща заявка**. Той разделя даден адрес на части като текст.

Запишете файла като `url_parts.py`:

```python
from urllib.parse import urlsplit

# Адрес за анализ; не се осъществява мрежова връзка.
url = 'https://example.com/catalog/item.html'
parts = urlsplit(url)

# Показваме трите основни части на адреса.
print('Схема:', parts.scheme)
print('Сървър:', parts.hostname)
print('Път:', parts.path)
```

Стартирайте:

```shell
python url_parts.py
```

Очакван резултат:

```text
Схема: https
Сървър: example.com
Път: /catalog/item.html
```

### Обяснение на ключовите редове

| Код | Значение |
|---|---|
| `from urllib.parse import urlsplit` | Зарежда готова функция от стандартната библиотека |
| `url = '...'` | Запазва адреса като текст |
| `parts = urlsplit(url)` | Разделя адреса на части |
| `parts.scheme` | Дава схемата |
| `parts.hostname` | Дава името или IP адреса без порта |
| `parts.path` | Дава пътя |

Заменете адреса с `http://127.0.0.1:8000/index.html`. Очаквайте `http`, `127.0.0.1` и `/index.html`.

> **Честа грешка:** Успешното изпълнение на този код не доказва, че сървърът работи. Разчитането на текст и изпращането на мрежова заявка са различни действия.

## 9. Как това се свързва с бъдещите уеб приложения?

```text
Браузър                               Сървър
HTML + CSS + Vue                      Python + Django
       │                                     │
       └──── заявки чрез Axios ─────────────→│
       ←──────── HTTP отговори ──────────────┘
```

**Django** ще обработва заявки на сървъра. **Vue** ще помага за обновяване на интерфейса в браузъра, а **Axios** — за изпращане на заявки от JavaScript. **Bootstrap** ще улеснява оформлението на страниците. Днес е важно само да разграничавате клиентската и сървърната страна.

**Минизадача 1:**

- Първи адрес: `http`; `127.0.0.1`; `/help.html`. Портът е `8000`.
- Втори адрес: `https`; `example.com`; `/courses/python.html`.

**Минизадача 2:**

```text
Браузър ── HTTP заявка за /index.html ──→ Python сървър
Браузър ←── HTTP отговор с HTML ───────── Python сървър
```

## Най-важното в три изречения

**Клиентът изпраща заявка, а сървърът връща отговор.**  
**В URL разпознаваме схема, сървър и път към ресурс.**  
**HTTPS защитава комуникацията, но не гарантира достоверността на съдържанието.**
