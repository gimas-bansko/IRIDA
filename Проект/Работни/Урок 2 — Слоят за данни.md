## Въведение

В реалните приложения данните трябва да се пазят надеждно: потребители, продукти, оценки, поръчки и други. Слоят за данни организира връзката между програмния код и базата данни, така че разработчикът да работи с Python обекти вместо да пише SQL за всяка операция.

В Django тази задача се изпълнява чрез **модели**, **менажери** и **ORM**. Те правят кода по-четим, по-лесен за поддръжка и по-независим от конкретната база данни.

## След този урок ще можете да...

- създавате базов Django модел;
- създавате и извличате записи чрез менажера `objects`;
- проверявате ORM заявки чрез Django shell.

# 1. Какво е слой за данни?

**Слоят за данни** (_Data Access Layer_, DAL) е частта от приложението, която отговаря за съхраняването, извличането и промяната на данни в база данни.

В многослойно приложение отделните части имат различни отговорности:

```text
Потребител
    ↓
Потребителски интерфейс (templates / frontend)
    ↓
Бизнес логика (views / services)
    ↓
Слой за данни (models / managers / ORM)
    ↓
База данни (SQLite, PostgreSQL, MySQL и др.)
```

## Защо разделяме приложението на слоеве?

- Всеки слой има ясна задача.
- Кодът е по-лесен за тестване и промяна.
- Интерфейсът не трябва да знае как точно се пазят данните.
- Можем да сменим базата данни с минимални промени в приложния код.

> **Пример:** Страница показва списък с книги. Тя не чете директно таблица в базата данни. View извиква модел или менажер, а те извличат нужните записи.

# 2. Основни понятия

## 2.1. Модел (Model)

**Моделът** е Python клас, който описва какви данни ще съхраняваме. Обикновено един модел съответства на една таблица в релационната база данни.

```python
class Book(models.Model):
    title = models.CharField(max_length=120)
```

В този пример:

- `Book` е модел;
- `title` е поле;
- Django ще създаде таблица за книгите след изпълнение на миграции.

## 2.2. Поле (Field)

**Полето** описва една характеристика на обекта. В база данни то обикновено съответства на колона в таблица.

Примери:

- заглавие на книга;
- име на автор;
- година на издаване;
- наличност на продукт.

## 2.3. Запис / инстанция

**Записът** е конкретен обект, създаден по даден модел. Ако `Book` е модел, една конкретна книга е запис (инстанция) на този модел.

```python
book = Book(
    title='Python за начинаещи',
    author='Анна Петрова',
    published_year=2025
)
```

Преди `book.save()` този обект съществува само в паметта на програмата. След `book.save()` той се записва в базата данни.

## 2.4. ORM

**ORM** означава _Object-Relational Mapping_ – обектно-релационно съпоставяне. Това е механизъм, който позволява да работим с таблици чрез Python класове и обекти.

```text
Python клас Book     ↔     Таблица в базата данни
Python поле title    ↔     Колона title
Python обект book    ↔     Един ред (запис)
```

Вместо да пишем SQL като:

```sql
SELECT * FROM books_book;
```

в Django използваме Python код:

```python
Book.objects.all()
```

## 2.5. Менажер (Manager)

**Менажерът** е обект, чрез който изпълняваме ORM операции към модел. Всеки Django модел има стандартен менажер с име `objects`.

```python
Book.objects.all()
Book.objects.create(title='Django основи', author='Иван Георгиев', published_year=2024)
```

Менажерът ни позволява да:

- създаваме записи;
- извличаме всички записи;
- филтрираме записи;
- търсим конкретен запис;
- сортираме резултати;
- броим записи.

# 3. Django модел: синтаксис и пример

Моделите обикновено се дефинират във файла `models.py` на Django приложението.

## 3.1. Примерен модел `Book`

```python
# library/models.py
from django.db import models


class Book(models.Model):
    # Кратък текст. max_length е задължителен за CharField.
    title = models.CharField(max_length=120)

    # Име на автора.
    author = models.CharField(max_length=80)

    # Само неотрицателни цели числа.
    published_year = models.PositiveIntegerField()

    # Логическа стойност: True или False.
    is_available = models.BooleanField(default=True)

    def __str__(self):
        # Прави обекта четим при показване в Django admin и shell.
        return f'{self.title} — {self.author}'
```

### Обяснение на ключовите редове

- `from django.db import models` – импортира инструментите за създаване на модели.
- `class Book(models.Model):` – създава модел, който наследява `models.Model`.
- `CharField` – поле за кратък текст; изисква `max_length`.
- `PositiveIntegerField` – поле за неотрицателни цели числа.
- `BooleanField` – поле със стойност `True` или `False`.
- `default=True` – начална стойност при създаване на нов запис.
- `__str__` – определя четим текст, който представя обекта.

# 4. От модел до таблица: миграции

След всяка промяна в `models.py` трябва да синхронизираме структурата на базата данни.

## Основна последователност

```text
1. Променяме models.py
        ↓
2. Създаваме миграция
        ↓
3. Прилагаме миграцията към базата данни
```

## Команди

```bash
# Създава файл с описание на промяната в моделите.
python manage.py makemigrations

# Прилага миграциите към базата данни.
python manage.py migrate
```

### Каква е разликата?

- `makemigrations` **подготвя** миграция: Django открива какво е променено в моделите.
- `migrate` **прилага** миграцията: Django създава или променя таблиците в базата данни.

> **Важно:** Ако промените модел, но не изпълните миграции, промените няма да се отразят в базата данни.

# 5. Работа с данни чрез Django shell

Django shell е интерактивна Python среда, в която работим с настройките и моделите на проекта.

```bash
python manage.py shell
```

## 5.1. Импортиране на модел

```python
from library.models import Book
```

## 5.2. Създаване на запис с `create()`

```python
book = Book.objects.create(
    title='Python за начинаещи',
    author='Анна Петрова',
    published_year=2025,
    is_available=True
)
```

`create()` едновременно:

1. създава Python обект;
2. записва го в базата данни.

## 5.3. Създаване чрез `save()`

```python
book = Book(
    title='Django на практика',
    author='Иван Георгиев',
    published_year=2024
)

book.save()
```

Този подход е полезен, когато искаме първо да създадем или променим обекта и след това да решим кога да го запишем.

## 5.4. Извличане на всички записи

```python
all_books = Book.objects.all()
print(all_books)
```

`all()` връща **QuerySet** – колекция от резултати, върнати от ORM заявка.

## 5.5. Филтриране на записи

```python
available_books = Book.objects.filter(is_available=True)
print(available_books)
```

`filter()` връща всички записи, които отговарят на условието. Ако няма такива записи, резултатът е празен QuerySet, а не грешка.

## 5.6. Намиране на един конкретен запис

```python
book = Book.objects.get(pk=1)
print(book)
```

`pk` означава _primary key_ (първичен ключ). Django автоматично създава уникално поле `id`, ако не сме задали друго.

> `get()` се използва само когато очакваме точно един резултат. Ако няма такъв или има повече от един, Django връща грешка.

## 5.7. Сортиране и броене

```python
# Сортиране по година – от най-новата към най-старата.
newest_books = Book.objects.order_by('-published_year')

# Брой на всички книги.
book_count = Book.objects.count()
```

Знакът `-` пред името на полето означава низходящ ред. Без `-` сортирането е възходящо.

# 6. Връзка между Python обекти, ORM и база данни

| В Python / Django | В релационната база данни | Пример |
|---|---|---|
| Модел | Таблица | `Book` → таблица за книги |
| Поле | Колона | `title` → колона за заглавие |
| Инстанция | Ред / запис | една конкретна книга |
| Менажер | Достъп до заявки | `Book.objects` |
| ORM заявка | SQL операция | `Book.objects.filter(...)` |
| Миграция | Промяна в структурата | създаване на таблица / колона |

# 7. Внимание: чести грешки и добри практики

## Чести грешки

### 1. Забравени миграции

Променили сте `models.py`, но получавате грешка за липсваща колона или таблица.

**Решение:**

```bash
python manage.py makemigrations
python manage.py migrate
```

### 2. Липсващ `max_length` при `CharField`

Неправилно:

```python
name = models.CharField()
```

Правилно:

```python
name = models.CharField(max_length=100)
```

### 3. Моделът не е в регистрирано приложение

Приложението трябва да присъства в `INSTALLED_APPS` във файла `settings.py`. Иначе Django може да не открие моделите и миграциите.

### 4. Грешен импорт в Django shell

Ако моделът е в приложението `games`, импортът е:

```python
from games.models import Game
```

### 5. Неподходящо използване на `get()`

Неправилно е да използваме `get()` при търсене на много записи:

```python
# Може да върне грешка, ако има повече от една Puzzle игра.
Game.objects.get(genre='Puzzle')
```

Правилно:

```python
Game.objects.filter(genre='Puzzle')
```

## Добри практики

- Използвайте ясни и описателни имена: `published_year`, а не `py`.
- Именувайте класовете модели в **единствено число**: `Book`, `Game`, `StudentProject`.
- Използвайте `__str__`, за да виждате разбираемо представяне на обектите.
- Подбирайте подходящ тип поле според данните.
- Изпълнявайте миграции след промяна в моделите.
- Не записвайте чувствителни данни като пароли в обикновени текстови полета.
- Не редактирайте директно таблиците, когато упражнявате работа през Django модели; поддържайте промените чрез модели и миграции.

# 8. Cheatsheet: речник и бърза справка

| Термин / синтаксис | Значение | Кратък пример |
|---|---|---|
| Data Access Layer | Слой за работа с трайно съхранявани данни | модели + ORM + база данни |
| Модел | Python клас, описващ данни | `class Book(models.Model):` |
| Поле | Характеристика на модел; колона в таблица | `title = models.CharField(max_length=120)` |
| Инстанция | Конкретен запис на модел | `book = Book(...)` |
| ORM | Работа с база данни чрез Python обекти | `Book.objects.all()` |
| Менажер | Обект за ORM заявки | `Book.objects` |
| `create()` | Създава и записва обект | `Book.objects.create(...)` |
| `all()` | Връща всички записи | `Book.objects.all()` |
| `filter()` | Връща записи по условие | `Book.objects.filter(is_available=True)` |
| `get()` | Връща точно един запис | `Book.objects.get(pk=1)` |
| `order_by()` | Сортира резултати | `Book.objects.order_by('-published_year')` |
| `count()` | Връща броя записи | `Book.objects.count()` |
| `makemigrations` | Подготвя миграция | `python manage.py makemigrations` |
| `migrate` | Прилага миграциите | `python manage.py migrate` |

# Обобщение

- Слоят за данни свързва приложението с базата данни.
- Django моделите описват структурата на данните.
- Полетата описват характеристиките на обектите.
- Django ORM превръща Python операции в заявки към базата данни.
- Менажерът `objects` предоставя основните операции за работа със записи.
- След промяна на модел изпълняваме `makemigrations` и `migrate`.
