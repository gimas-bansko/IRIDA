---

## Цели и критерии за успех

След изпълнение на работния лист ще мога да:

- изпратя `GET`, `POST`, `PUT` и `DELETE` заявка чрез конзолен HTTP клиент;
- разчета URL, метод, заглавка, JSON тяло, статус код и JSON отговор;
- свържа методите с CRUD операциите: Create, Read, Update, Delete;
- разпозная вероятна причина и следваща стъпка при отговори `401`, `404` и `500`.

**Критерий за успех:** Изпълнил/а съм задачите от избраното ниво, запазил/а съм използваните команди и съм обяснил/а какво означава всеки получен статус код.

> **Важно:** JSONPlaceholder е тестов API. При `POST`, `PUT` и `DELETE` може да получите логичен отговор, но данните обикновено не се запазват трайно на сървъра.

Създайте файл `api-check.sh` за Linux/macOS/Git Bash **или** файл `api-check.ps1` за PowerShell. Скриптът трябва да изпраща поне четири заявки към JSONPlaceholder и след всяка да извежда:

3. `PUT /posts/1` с валидно JSON тяло — очакване: успешна промяна;
4. `DELETE /posts/1` — очакване: успешна заявка за изтриване.

### Допълнителна диагностика

| `500 Internal Server Error` | | |

### Примерен Bash вариант

```bash
#!/usr/bin/env bash

base_url='https://jsonplaceholder.typicode.com'

request() {
  local operation="$1"
  shift

  echo
  echo "=== ${operation} ==="
  echo "Команда: curl $*"

  # -s: без лента за напредък; -o: записва тялото временно;
  # -w: отпечатва само статуса след края на тялото.
  status=$(curl -s -o response.json -w '%{http_code}' "$@")
  echo "Статус: ${status}"

  if [[ "$status" =~ ^2 ]]; then
    echo 'Резултат: очакван успешен отговор.'
  else
    echo 'Резултат: провери URL, метод, заглавки, тяло и права за достъп.'
  fi

  echo 'Тяло на отговора:'
  cat response.json
  echo
}

request 'GET: публикация 1' "${base_url}/posts/1"
request 'POST: нова публикация' -X POST "${base_url}/posts" \
  -H 'Content-Type: application/json' \
  -d '{"title":"API тест","body":"Скриптова проверка","userId":12}'
request 'PUT: обновяване на публикация 1' -X PUT "${base_url}/posts/1" \
  -H 'Content-Type: application/json' \
  -d '{"id":1,"title":"Обновено","body":"Нов текст","userId":1}'
request 'DELETE: публикация 1' -X DELETE "${base_url}/posts/1"
```

> Ако работите в PowerShell, може да използвате `curl.exe`, за да извикате действителния curl, а не PowerShell псевдоним.

---

### 2. Синтактична шпаргалка

| Цел | Конзолна команда / правило | Какво да проверя |
|---|---|---|
| GET: прочитане | `curl -i https://jsonplaceholder.typicode.com/posts/1` | URL е пълен и съдържа `https://`; `-i` показва заглавките. |
| POST: създаване | `curl -i -X POST URL -H 'Content-Type: application/json' -d '{"title":"..."}'` | Методът е `POST`; има `Content-Type`; JSON е валиден. |
| PUT: обновяване | `curl -i -X PUT URL/ID -H 'Content-Type: application/json' -d '{...}'` | В URL има правилно `ID`; изпращам цялото необходимо тяло. |
| DELETE: изтриване | `curl -i -X DELETE URL/ID` | Методът е `DELETE`; проверявам дали ID е правилният. |
| Показване на статуса | `curl -s -o /dev/null -w '%{http_code}\n' URL` | Командата извежда само HTTP статус кода. |

**JSON правила:** ключовете и текстовите стойности са в двойни кавички; между полетата има запетая; последното поле няма запетая.

Валиден пример:

```json
{
  "title": "Моята публикация",
  "body": "Текст на публикацията",
  "userId": 12
}
```

### 3. Топ 3 чести грешки и поправки

| Симптом / грешка | Вероятна причина | Точно действие за поправка |
|---|---|---|
| Получавам `404 Not Found` | URL е сгрешен, ресурсът не съществува или ID е невалидно. | Копирай базовия URL `https://jsonplaceholder.typicode.com`; провери пътя `/posts/5`; сравни ID с условието. |
| Получавам `400 Bad Request` или сървърът не разбира данните | JSON тялото е невалидно или липсва `Content-Type: application/json`. | Провери двойните кавички, запетаите и скобите; добави `-H 'Content-Type: application/json'`. |
| Командата се изпълнява, но не виждам нужната информация | Не използваш `-i`, методът не е зададен или изходът не е прегледан. | Добави `-i`; за POST/PUT/DELETE използвай `-X МЕТОД`; намери първия ред `HTTP/...` и JSON тялото под заглавките. |

### 4. Какво означават някои статуси?

| Статус | Кратко значение | Най-подходяща следваща стъпка |
|---|---|---|
| `200 OK` | Заявката е обработена успешно. | Провери дали тялото съдържа очакваните данни. |
| `201 Created` | Създаден е нов ресурс. | Провери върнатото `id` и съдържанието на обекта. |
| `401 Unauthorized` | Липсват, невалидни са или са изтекли данни за удостоверяване. | Провери дали API изисква ключ/токен и не публикувай секретни данни в кода. |
| `404 Not Found` | Пътят или ресурсът не е намерен. | Провери URL, правописа, версията на API и идентификатора. |
| `500 Internal Server Error` | Възникнал е проблем на сървъра. | Запиши статус, URL, метод и час; провери документацията/статуса на услугата; не променяй произволно заявката. |
